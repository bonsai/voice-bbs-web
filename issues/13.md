# Issue #13: デプロイ戦略 — Home deploy & hands-off CI/CD

**Status:** OPEN
**Label:** deploy
**Created:** 2026-09-01

## 前提
- インフラは Cloudflare のみ（Pages + D1 + R2）
- 無料枠で運用する
- 開発者は「家でデプロイする」（ローカルPCから手動運用）

---

## 推奨：GitHub → Pages 自動連携（ほぼ hands-off）

Cloudflare Pages は **Git 連携** を持っている。`master` push → 自動 build → deploy。

### なぜこれが最強か
- コードを push するだけで、あとは勝手に deploy される
- `wrangler.toml` を置いておけば、D1/R2 binding も解決される
- 手動 deploy を忘れても自動で追従

### 必要な設定
1. Cloudflare Dashboard → Pages → `Create a project` → `Connect to Git`
2. `voice-bbs-web` repo を選択
3. Build settings:
   - Build command: `cd apps/web && npm run build`
   - Build output directory: `apps/web/out`
4. D1 binding: `DB = <voice-bbs-db>`
5. R2 binding: `BUCKET = <voice-bbs-audio>`
6. Environment variable: `R2_PUBLIC_URL = https://pub-xxx.r2.dev`

### 制約
- ブランチ push → deploy まで 30~60 秒
- 初回 D1 migration は手動（`wrangler d1 migrations apply --remote`）

---

## 代替：手動 deploy（ローカルから一発）

家のPCで完結したい場合、`wrangler` CLI を使う。

### 事前準備
```bash
# Cloudflare API token 取得（Dashboard → My Profile → API Tokens）
# 権限: Cloudflare Pages:Edit, D1:Edit, R2:Edit
npx wrangler login
```

### 手動 deploy フロー
```bash
cd apps/web

# 1. build
npm run build

# 2. migration（初回＆スキーマ変更時のみ）
npx wrangler d1 migrations apply voice-bbs-db --remote

# 3. deploy（Pages + Functions）
npx wrangler pages deploy out
```

### ポイント
- `out/` に Next.js static export 済みの HTML + JS が含まれる
- `functions/` 内の Hono API は Pages Functions として自動バンドルされる
- `wrangler.toml` の bindings が紐付けられる

## GitHub Actions（完全 hands-off、好みで選ぶ）

Git連携を使わずに GitHub Actions で CF Pages にデプロイすることも可能。

### `.github/workflows/deploy.yml`
```yaml
name: Deploy to Cloudflare Pages

on:
  push:
    branches: [master]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: cd apps/web && npm ci && npm run build
      - name: Deploy to Cloudflare Pages
        uses: cloudflare/pages-action@v1
        with:
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          projectName: voice-bbs-web
          directory: apps/web/out
          branch: master
```

### Secrets 要設定
- `CLOUDFLARE_ACCOUNT_ID`: Dashboard URL の `dash.cloudflare.com/XXXX`
- `CLOUDFLARE_API_TOKEN`: Pages:Edit + D1:Edit 権限

### 優先度
- ** auto-deploy推奨**：Pages Git連携が最もシンプルで安定している
- Actions：Git連携では対応できない複雑なフローが必要な場合のみ

---

## 結論：bonsai さんの場合

「家で手動」＝ `wrangler pages deploy out` 一発でも良いが、
**Git連携にしておけば push するだけなので、結局一番手間がない。**

### 推奨セットアップ
1. Cloudflare Pages で Git 連携（ボタンぽちぽち）
2. `wrangler.toml` の `database_id` を本番 D1 の ID に差し替え
3. 本番 D1 に migration apply（初回のみ手動）
4. `R2_PUBLIC_URL` を本番の public URL に設定
5. `git push origin master` → 自動 deploy

## D1 migration リモート適用手順
```bash
cd apps/web
# 本番DB作成後にID取得
npx wrangler d1 create voice-bbs-db
# wrangler.toml の database_id を更新

# migration apply
npx wrangler d1 migrations apply voice-bbs-db --remote
```
