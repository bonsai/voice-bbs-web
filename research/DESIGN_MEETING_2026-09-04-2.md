## プロセス記録（Design DX）

### 1. リサーチフェーズ

#### 手法
- **最初**: Dribbble/Behance へのブラウザアクセス
  - 結果: DuckDuckGo が bot 検知でブロック
- **転換**: curl + DuckDuckGo HTML 検索
  - 結果: 検索結果は取得できたが、Dribbble ページ自体はブロック
- **最終**: 既存スクリーンショットからの分析 + プロトタイプ直実装

#### 使用ツール
| ツール | 用途 | 結果 |
|--------|------|------|
| curl + DuckDuckGo | 検索クエリ実行 | 成功（ただし Dribbble はブロック） |
| ブラウザ MCP | 画像収集 | 成功（clubhouse/voice-chat） |
| pyautogui | スクリーンショット | 成功 |
| diffusers (SD) | UI 画像生成 | CPU で数分→中止（非現実的） |

#### 問題解決
- **ブロック対策**: 検索クエリ自体は curl で取得可能
- **画像生成**: CPU では SD が遅い → CSS プロトタイプに切り替え
- **代替案**: HTML/CSS で即実装→ブラウザで確認→高速フィードバック

### 4. 意思決定フェーズ

#### 最終評価
| 案 | スコア | 評価 |
|----|--------|------|
| 案 A | 17/25 | 良いが奥行きが物足りない |
| **案 B** | **22/25** | **採用** — 最も Voice BBS のコンセプトに適合 |
| 案 C | 19/25 | 重厚だが親しみ薄れがち |

#### 決定理由
1. Voice BBS の「泡」コンセプトに最も近い（透明感 + 奥行き）
2. ネオンエッジで音声メッセージのハイライトに最適
3. カテゴリカラー（紫/青/ピンク）との相性が良い
4. カードのアクセントカラーをネオンで表現可能

## プロセスの反省

### 良かったこと
- ✅ 検索ツールを柔軟に切り替え（ブラウザ→curl→プロトタイプ）
- ✅ SD 画像生成は CPU で非現実的と判断し、CSS プロトタイプに転換
- ✅ 3 案を並べて比較することで視覚的に評価可能
- ✅ 評価基準を事前に定義し、数値で比較

### 改善点
- ⚠️ DuckDuckGo へのアクセスが最初からブロックされることを想定すべき
- ⚠️ SD 画像生成は Cloud API または GPU 環境が必要
- ⚠️ 案の比較表を HTML/CSS で作成したのは効率的だった

### 次回への教訓
- リサーチは curl ベースで始め、画像取得は MCP ブラウザに任せる
- プロトタイプは HTML/CSS で即実装→ブラウザ確認→高速フィードバック
- 意思決定は数値評価マトリックスで客観化
