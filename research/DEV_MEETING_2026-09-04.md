## 議題1: T-DS1(トークン適用)の進め方

- **設計者**: トークン v1 は定義済み。泡・シート・カードを semantic class 化して一元管理したい。見た目は「不変」が条件
- **実装者**: 泡はインライン style(位置/サイズ/色が動的)のため、class 化できるのは 静的スタイル(影・縁・radius)のみ。全面置換は回帰リスク。テストは見た目を検証しない(手動確認のみ)
- **合意**: ①静的スタイルのみ class 化し、動的値は CSS 変数(style で渡す)に置換 ②既存 21 テスト+ビルド緑を維持 ③preview で見た目差分を人間確認 → OK で本番反映

## 議題2: UX(B 主軸)と初回ガイド

- **実装者**: Sprint 1 でガイド導入済み(localStorage 1回)。次は「泡が密で空きがない」ケースの実測がまだ
- **設計者**: ガイドの位置づけを「操作の保障」に。録音失敗(小さすぎ/短すぎ)時のフォロー文言も一貫させる
- **合意**: 次の実装は ①T-DS1 ②録音失敗リトライ導線(再試行ボタン)の順

## 議題3: PWA 適用範囲(D4)

- **設計者**: インストール導線・manifest・オフライン=閲覧のみ想定。録音/投稿はオンライン前提
- **実装者**: SW 導入は配信キャッシュ戦略(cache-first for /api/audio?)と要相談。まずは manifest+アイコン+インストール UI から
- **合意**: Phase 1 = manifest/icons/インストール導線のみ。SW は Phase 2(オフライン閲覧)。D4 は「a: オフラインは閲覧のみ」で仮決定、会議ログに記録

## 議題4: バックエンド委譲の境界

- **実装者**: BE1〜7 は別担当へ。フロントが触るのは functions の削除API(済)のみ
- **設計者**: API 契約(openapi.yaml)を委譲先への接続点として正式化する
- **合意**: `apps/web-next` は誰も触らない。API 変更は web-vue functions + openapi.yaml を同時更新(委譲メモに追記)
